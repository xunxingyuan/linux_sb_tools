## 准确性约束

- 引用中的昵称、称号名称、主题标题先替换为占位符再匹配。例如用户名叫“称号”仍按打赏操作归类，购买名为“红包”的称号仍按购买归类。
- 不按金额大小猜来源，不把正数“购买称号”改为出售。明确文案与金额方向冲突时保留该类型并标记“方向待核对”。
- “退回奖励”在这里是扣回已发奖励，按实际负值记录；红包托管也与发布费用、领取、返现、退款分开。
- 未知原因显示“待分类／来源待识别”，其已识别金额仍参与收支合计，可在流水中按“待分类”筛选。
- 同文案中的引用内容合并展示，仅用于来源汇总；逐笔原文、关联主题与金额保持完整。CSV 同时带出大类、详细类型、状态与依据。页面不再展示单独的来源核对区块。
- 首次同步补齐旧账号缺少的 `pointsRows` 字段；保留既有称号历史、库存、设置。每页核对登录账号，保存时再次校验历史清除代次。

## 人物与主题归属

人物排行只归集明确的“用户「昵称」打赏了你的主题／回复”和“给用户「昵称」的主题／回复打赏”，并要求文案方向和积分正负一致。按原始昵称精确汇总，不对昵称做 Unicode 合并，也不凭主题作者猜红包发布者或投币者。幸运打赏奖励等系统记录不属于任何打赏用户。

关联主题排行以真实的 linux.sb 主题链接 ID 归集正向积分，明确排除幸运打赏奖励（即使记录附有主题链接）；点击排行后的流水明细也按同样口径过滤。幸运打赏奖励仍保留在总收入和分类统计中。回帖参数不同仍为同一主题；不从无链接标题推断主题身份。这里只表示关联主题带来的积分，不表示主题由当前用户创作。
